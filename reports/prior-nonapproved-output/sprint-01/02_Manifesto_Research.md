# Manifesto Research

## Purpose

Extract durable beliefs before architecture and implementation choices harden.

## Themes examined

Human agency, local ownership, intentional memory, bounded capability, observability, modularity, simplicity, replaceability and sustainable maintenance.

## Tensions

- convenience versus ownership;
- autonomy versus human control;
- useful memory versus accumulation and staleness;
- rich integration versus plugin sprawl;
- framework acceleration versus conceptual lock-in;
- first-domain pragmatism versus general-system distortion.

## Outcome

The manifesto should constrain future architecture without becoming a technical specification. It should change rarely and should be used when new technology makes the project direction ambiguous.
